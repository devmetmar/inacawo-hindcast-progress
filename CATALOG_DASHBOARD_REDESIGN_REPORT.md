## Existing dashboard problems

The previous `dashboard/public/index.html` emphasized:

- Overall acceptance / provisional remaining window
- Remaining and historical year status grids (often `UNKNOWN`)
- Workflow stages, team workload, HPC queue snapshot
- Generic project metrics

It did **not** answer operational catalog questions: which datasets are expected vs catalogued, creation/catalog/verification dates, incomplete products, per-dataset TODOs, owners/blockers, or year × product coverage with CLS vs internal separation.

## New dashboard structure

Static page regenerated by `python dashboard/generate.py`:

1. **Scope banner** — `PROVISIONAL / NOT CONFIRMED`; overall % suppressed
2. **Catalog overview** — expected year×product cells, catalogued, created (evidenced), verified, accepted, incomplete, open TODOs
3. **Dataset inventory** — searchable/filterable/sortable table
4. **Year × product matrices** — CLS historical and internal remaining, separate
5. **TODO / action tracker** — grouped by status; links to datasets
6. **Dataset details** — identity, inventory, lifecycle, timeline, linked TODOs
7. **Metric definitions**
8. **Secondary panel** (collapsed) — issues, remaining-stream metrics, workflow, workload, HPC

## How creation dates and lifecycle events are sourced

| Date | Source | Policy |
|------|--------|--------|
| `created_at` | Explicit field + provenance only | **Never** inferred from mtime, git, HPC start, or record creation |
| `catalogued_at` | Catalog registration date on the YAML | Set to `2026-11-23` for records registered at discovery |
| `last_inventory_scan` | Inventory activity | Set to `2026-11-23` where discovery scanned directories |
| `verified_at` / `accepted_at` | Explicit only | Remain null until evidenced |
| Timeline | Evidenced fields + `data/activity_log/` | Unknown timestamps labeled `UNKNOWN` |

Lifecycle is either explicit `lifecycle_status` or conservatively derived (`CATALOGUED` if record exists; `INCOMPLETE` when notes/status say so; `VERIFIED`/`ACCEPTED` only from integrity/validation evidence). States are **not** auto-advanced.

## How TODOs relate to datasets

- Tasks list `related_dataset_ids`.
- Datasets may list `related_task_ids`.
- `scripts/lib/catalog.py` unions both directions (no fuzzy title matching).
- Dashboard shows open TODO counts per dataset and navigable links both ways.

## Historical / internal separation

- Origins displayed as `CLS_HISTORICAL` (`cls_brazil`) vs `INTERNAL_HINDCAST` (`internal`).
- Separate year × product matrices for `historical_baseline` and `remaining_internal` periods.
- Non-postprocessed categories (`run_dirs`, `forcing`, `other`) remain in the inventory but are not treated as equivalent postprocessed matrix products.
